# RL Email Assembly

Builds all three actual emails inside Figma — Teaser, Product Focus, Reminder — each with logo, Hero, and however many content modules the Campaign Plan calls for (fixed: 0/2/1 respectively, see `rl-brand-copy`'s `module-types.md`), composed from the "Test - RLNA Email DS" component library, then grouped and dropped into the campaign section's matching `Email design N` frame.

## Inputs this skill expects
- A Campaign Plan from `rl-brand-copy` covering all three emails (module list, copy, brand/sub-line, one shared palette).
- A campaign section already created by `rl-campaign-scaffolding` (has three empty `Email design 1`/`Email design 2`/`Email design 3` frames waiting, plus the three SL/PH pairs already filled).
- The RLNA Email Design System library file URL (ask if not given — this skill can't discover it on its own, same as any other Figma file).

## Workflow — repeat for each of the three emails
Build Email 1 (Teaser) fully, then Email 2 (Product Focus), then Email 3 (Reminder) — one at a time, not interleaved, so a failure in one doesn't leave a half-built mix of all three.

1. **Identify brand + sub-line + which visual tier** (Core vs Lux, Light vs Dark, and for Luxe Brands specifically which typography track — Founders or Sackers) from the Campaign Plan — same for all three emails in the set.
2. **Read `module-library.md`** for the current component map, then the matching brand file (`polo.md`/`lauren.md`/`home.md`/`luxe-brands.md`) for type scale, color, and padding specs. Also note the **Core App Banner + Navigation Footer** fixed pair, staged same-file in the template's "Footer Emails" section (see `module-library.md`) — every one of the three emails ends with it.
3. **Check page "08 Templates Emails complete" for a matching pre-assembled template before building module-by-module.** If one fits the brand and roughly this email's shape (remember: Teaser is Hero-only, Product Focus is Hero+2, Reminder is Hero+1), import and detach that single component and edit it in place — far less work than composing from scratch. Only fall back to step 4 when nothing there fits well. A pre-assembled template may include its own footer — if so, swap it for the Core App Banner + Navigation Footer pair rather than leaving the template's own footer in place, so all three emails end consistently.
4. **Import and place one component per tool call** — header, then Hero (`01 Primary/Primary`), then Hero CTA(s) (`03 CTAs/01 Primary`, skip for the Teaser if its Hero has no CTA), then each subsequent module + its CTA(s) (Product Focus and Reminder only), then the Core App Banner + Navigation Footer pair last (cloned same-file from the template's "Footer Emails" section, not cross-file — see `module-library.md`). Never batch multiple imports in one script (see `module-library.md`'s gotcha — a later failure erases earlier successes in the same call). Always verify DSK vs MOB by the component's actual width, not its variant label.
5. **Fill in copy** using the font-substitution technique in `figma-workflow.md` (standing defaults: Le Jeune Deck → Playfair Display, Founders Grotesk Mono → Space Mono, Founders Grotesk Text Core body/eyebrow → Space Grotesk — apply directly, no re-testing; see that file for the one still-unresolved Luxe Brands case). **Apply the Campaign Plan's shared PALETTE** to every module's copy/CTA background consistently across all three emails — see `figma-workflow.md`'s color section; don't let individual modules, or individual emails within the set, drift to their own colors.
6. **Place images** once that's in scope — same `upload_assets` → `curl` pattern as everything else, verify `placedOnNodeId` before trusting it landed, apply the framed-vs-bleed treatment per `module-library.md` if the brief calls for it. Remember the Reminder's Hero image is allowed to be a different shot than the other two emails' — use whatever the Campaign Plan specified for that email, don't default to reusing Email 1's or Email 2's image without checking the plan.
7. **Group this one email's module instances into its own frame**, convert it to vertical auto-layout, name it per the fiscal naming convention, resize the Hero image to at least 788px tall, match the header's background and logo color to the campaign's shared palette (white logo on a dark header background, navy/brand-default logo on a light one), sweep every CTA/underline for un-updated stroke colors (not just fills), and move it into the scaffolded section's **matching `Email design N` frame at `x: 543, y: 216`** (relative to that frame — `Email design 1` for Teaser, `Email design 2` for Product Focus, `Email design 3` for Reminder) — see `module-library.md`'s final-polish checklist for exact detail on each of these.
8. **Confirm with a screenshot** of this one assembled email before moving to the next.

Once all three are placed, **screenshot the whole section** (all three `Email design` columns together) as the final confirmation — this is what the run's summary/webhook should reference, as one link to the section rather than three separate ones.

## Reference index
- `module-library.md` — the component map for the design-system library: pages, module variants, the DSK/MOB-naming-is-inconsistent gotcha, the one-import-per-call gotcha, the manual framed-vs-bleed technique, the confirmed Hero/Module composition pattern, and the Core App Banner + Navigation Footer fixed pair.
- `figma-workflow.md` — general tested technique: cross-file component import, image upload and its known first-attempt-silently-fails quirk, font substitution (including which substitutes are standing defaults vs. still unresolved), color-matching a module background to actual campaign imagery, texture-only image cropping.
- `polo.md`, `lauren.md`, `home.md`, `luxe-brands.md` — visual build spec per brand: typography, hex colors, type scale, sizes, padding, fixed modules. Voice/tone/story for these brands lives in the `rl-brand-copy` skill instead, not here.

## What this skill deliberately does not do
No copy decisions, no module-count/story judgment calls (that's `rl-brand-copy`'s Campaign Plan, taken as input here — including the fixed Teaser/Product Focus/Reminder shapes), no section creation/naming/SL-PH/timeline (that's `rl-campaign-scaffolding`). If the Campaign Plan is missing, ambiguous, or the section isn't scaffolded yet, say so rather than improvising either of those upstream jobs.
